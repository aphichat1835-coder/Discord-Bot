🔴 BUG วิกฤต
Bug S-1: ❗ setLogChannelMap ไม่มี — มีแค่ saveLogChannelMap
ฟังก์ชันชื่อ:
async function saveLogChannelMap(guildId, channels) {
    await LogChannelMapModel.updateOne(
        { guildId },
        { $set: { ...channels, updatedAt: Date.now() } },
        { upsert: true }
    );
}

แต่ utility.js เรียกแบบนี้:
await sessionManager.setLogChannelMap(interaction.guild.id, cat, ch.id);

ปัญหา:
ชื่อต่างกัน (set vs save)
Argument signature ต่างกัน — saveLogChannelMap รับ object แต่ utility ส่ง 3 args
Export ไม่ได้ export setLogChannelMap → /setup-log แครชทันที
🩹 แก้: เพิ่มฟังก์ชันใน sessionManager.js:
async function setLogChannelMap(guildId, category, channelId) {
    const key = `${category}ChannelId`;
    await LogChannelMapModel.updateOne(
        { guildId },
        { $set: { [key]: channelId, updatedAt: Date.now() } },
        { upsert: true }
    );
}

แล้ว export ด้วย
Bug S-2: connectDB() ลบ keepAlive: true ไปแล้ว แต่ comment ยังบอกว่ามี
// เฟส 14: keepAlive กันหลุด + เฟส 20: maxPoolSize กัน connection หมด
await mongoose.connect(process.env.MONGO_URI, {
    serverSelectionTimeoutMS: 5000,
    maxPoolSize: 20,
    minPoolSize: 2
});

ปัญหา: Mongoose 6.x+ ตัด useNewUrlParser, useUnifiedTopology, keepAlive ออกไปแล้ว (deprecated)
→ คอมเมนต์ภาษาไทย misleading แต่โค้ดถูก ✅
→ แต่ใน free-tier MongoDB Atlas — ถ้า idle 10 นาที จะตัด → ไม่มี keepAlive จริงๆ → DB จะ reconnect ทุกครั้งที่ใช้
🩹 แก้: เพิ่ม socketTimeoutMS: 45000 เพื่อช่วย handle dropped connection
🟠 Bug รอง
Bug S-3: saveDatabase() ทำ updateOne ทีละตัวใน loop — ช้ามาก
for (const [id, session] of sessions) {
    await SessionModel.updateOne(...);
}

ถ้ามี 20 sessions → 20 round-trips เรียงกัน
🩹 แก้: ใช้ bulkWrite() ลด round-trip เหลือ 1 ครั้ง
Bug S-4: getSession() มี side-effect ที่ขัด principle
function getSession(sessionId) {
    const s = sessions.get(sessionId);
    if (s) s.lastActivity = Date.now();  // ← side effect!
    return s;
}

ทุกคน "อ่าน" session = อัปเดต lastActivity ตลอด → idle timeout ไม่มีวันถึง
ผลกระทบ: cleanupIdleSessions ไม่เคยลบอะไรเลย เพราะ healthCheck เรียก getSession() ทุก 90 วินาที
🩹 แก้: แยกเป็น getSession() (อ่านอย่างเดียว) + touchSession() (อัปเดต activity)
