🏗️ โครงสร้าง Log ที่มีอยู่
ระบบมี log 2 ชั้น ที่แยกจากกันโดยสิ้นเชิง:
ชั้นที่ 1 — Audit Logger (auditLogger.js) → log เหตุการณ์ Discord อัตโนมัติ (message ลบ, member เข้าออก, voice state)
ชั้นที่ 2 — Command Log → log เมื่อใช้คำสั่ง (ban/kick/voicekickall) ส่งตรงไปช่อง

❌ ปัญหาที่ 1 — ใหญ่ที่สุด: invalidateAuditCache ไม่เคยถูกเรียกเลย
js// auditLogger.js บรรทัด 319 — export ออกมา แต่...
module.exports = { register, sendAuditLog, invalidateAuditCache: ... }

// ค้นทั้งโปรเจกต์ → ไม่มีที่ไหนเรียก invalidateAuditCache เลย
ผลที่เกิด: ตอนที่ผู้ใช้รัน /setup-log แล้วระบบสร้างช่อง log ใหม่ และบันทึก ID ลง MongoDB แล้ว — cache เก่าใน auditChannelCache Map ยังคงอยู่อีก 5 นาที (expiry = now + 300000)
ถ้า audit event เกิดขึ้นก่อน 5 นาทีผ่าน → ดึง cache เก่า → channelId เป็น null → ไม่ส่ง log ไปไหนเลย นี่คือสาเหตุหลักที่ "log ดูเหมือนไม่ทำงาน" หลัง setup

❌ ปัญหาที่ 6 — auditLogger.register() ถูกเรียกในช่วง ready แต่ถ้า throw error จะไม่ register
js// index.js ใน ready event

ถ้า restorePanels throw error → auditLogger.register จะไม่ถูกเรียกเลย และไม่มีการแจ้งว่า Audit Logger ไม่ได้ register

⚠️ ปัญหาที่ 7 — Intent GUILD_MESSAGE_REACTIONS หายไป (minor)
messageUpdate event ต้องการ partial message caching — ถ้า message ไม่อยู่ใน cache ของ discord.js, oldMsg.content จะเป็น null เสมอ ทำให้ if (oldMsg.content === newMsg.content) return; จะ skip ทุก edit ที่ message เก่าไม่อยู่ใน cache
