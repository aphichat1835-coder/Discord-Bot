🔴 BUG วิกฤต
Bug V-1: ❗ ดับเบิ้ลครอบ console.log/warn/error ใน voiceWorker — ชนกับใน index.js
index.js ทำแบบนี้:
const originalLog = console.log;
console.log = (...args) => {
    pushLog('info', msg);
    originalLog(...args);
};

voiceWorker.js (REGION 11) ก็ครอบซ้ำอีกชั้น:
const _origLog = console.log.bind(console);
console.log = (...args) => {
    _origLog(...args);
    // pushVoiceLog logic
};

ปัญหา:
ลำดับการ require สำคัญ — index.js require voiceWorker หลังครอบ console เสร็จแล้ว → voiceWorker ครอบทับอีกครั้ง → กลายเป็น 3 layer wrapper
Performance: ทุก console.log จะวิ่งผ่าน wrapper 2-3 ครั้ง → ช้าและกิน CPU
ที่อันตรายกว่า: voiceWorker._origLog เก็บ reference ตอน require → ถ้า require order เปลี่ยน อาจเก็บ wrapper ของ index แล้ว loop infinite
🩹 แก้: ย้าย voice log detection มาไว้ใน pushLog() ของ index.js หรือใช้ EventEmitter pattern แทน
Bug V-2: getSessionTokenHash() มี side-effect ใส่ tokenHash บน session object
function getSessionTokenHash(sessionId, session) {
    if (session.tokenHash) return session.tokenHash;
    const token = sessionManager.getToken(sessionId);
    if (token) {
        session.tokenHash = crypto.createHash('sha256').update(token).digest('hex');
        return session.tokenHash;
    }
    return null;
}

ปัญหา: เก็บ tokenHash ลงใน session object → แต่ session object ใน Map ไม่ใช่ persistent → reload จาก DB จะ recompute ทุกครั้ง (OK)
→ แต่ถ้า getToken() คืน null (DB หลุด) → จะคืน null → startSession throw TOKEN_DECRYPTION_FAILED
→ ผู้ใช้สับสนว่า token ผิด ทั้งที่ DB หลุด
🩹 แก้: แยก error message ระหว่าง "decrypt fail" และ "DB temporary unavailable"
Bug V-3: connectToVoice() ไม่ register VoiceConnectionStatus.Ready event log
ตอนเชื่อมต่อสำเร็จไม่มี log → pushVoiceLog('connect', ...) ใน console.log wrapper จับ pattern [WORKER] 🎧 Voice connected
แต่ pattern นี้ใช้ regex: Guild: (\S+) → จับเอา guildId มาเป็น sessionId
if (msg.includes('[WORKER] 🎧 Voice connected')) {
    const m = msg.match(/Guild: (\S+)/);
    pushVoiceLog('connect', m?.[1] || '?', 'Voice connected');
}

ปัญหา: m[1] คือ guildId ไม่ใช่ sessionId — แต่ pushVoiceLog ตั้งใจให้รับ sessionId → Voice Log จะแสดง guildId ผิด field
🩹 แก้: เปลี่ยน log message ใน startSession ให้พิมพ์ sessionId ด้วย:
console.log(`[WORKER] 🎧 Voice connected for Guild: ${session.serverId} Session: ${sessionId}`);
