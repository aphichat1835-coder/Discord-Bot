Bug A-1: ❗ messageDelete ไม่ filter ข้อความที่ระบบลบเอง (Anti-Raid bulkDelete) → log สแปม
ใน index.js Anti-Raid:
await message.channel.bulkDelete(5).catch(() => {});

→ auditLogger จับ messageDelete × 5 + messageDeleteBulk × 1 = 6 logs ต่อ 1 anti-raid event
🩹 แก้: ใส่ flag ใน global Set ก่อนสั่งลบ:
global.systemDeletes = global.systemDeletes || new Set();
global.systemDeletes.add(message.id);

แล้วใน auditLogger เช็ค if (global.systemDeletes.has(msg.id)) { skip; }
Bug A-2: guildMemberAdd ลงทะเบียน 2 ครั้ง — log สมาชิกใหม่ 2 รอบ
function registerMemberEvents() {
    client.on("guildMemberAdd", ...);  // ครั้งที่ 1 — log สมาชิก
}
function registerSecurityEvents() {
    client.on("guildMemberAdd", ...);  // ครั้งที่ 2 — log บอท
}

ปัญหา: ถ้า user (ไม่ใช่บอท) เข้า → ครั้งที่ 1 ทำงาน, ครั้งที่ 2 check if (!member.user.bot) return; ผ่าน
ถ้าบอท → ครั้งที่ 1 ทำงาน (log เข้า member channel), ครั้งที่ 2 log เข้า security channel → มี 2 log สำหรับบอท
ไม่ใช่ bug จริง — เป็น design intent (member channel + security channel) ✅

Bug R-1: ❗ handleModal modal_start ไม่ตรวจ ownership ของ Token
บรรทัด ~360:
async function handleModal(interaction, client) {
    if (interaction.customId === "modal_start") {
        const token = interaction.fields.getTextInputValue("token").trim();
        const serverId = interaction.fields.getTextInputValue("server_id").trim();
        const voiceId = interaction.fields.getTextInputValue("voice_id").trim();
        ...
        const sessionId = await sessionManager.createSession(
            token, serverId, voiceId, guildName,
            interaction.user.id,   // ← owner คือคนที่กดปุ่ม
            ...
        );

ปัญหา: ใครก็ตามที่กดปุ่ม "เริ่มการทำงาน" แล้วใส่ token ของคนอื่น จะกลายเป็น "owner" ของ session นั้น
→ คนอื่นกดดู Token ผ่าน /api/reveal-token (ที่ใช้แค่ PIN) → ขโมย token คนอื่น
ผลกระทบ:
ผู้ใช้ A เอา token ของผู้ใช้ B มาใส่ → B โดน A "เป็นเจ้าของ" session
A ใช้ Dashboard → reveal token → ได้ token B
A เข้าควบคุมบัญชี B ทันที
🩹 แก้: ต้องมี mechanism ยืนยัน:
Token validate กับ Discord API ก่อน → ดึง user.id จาก token จริง
เทียบกับ interaction.user.id → ถ้าไม่ตรง = reject
หรือง่ายกว่า: บอกใน Modal label ชัดเจน ว่า "ใส่ Token ของตัวเองเท่านั้น" + log warning ลง shadow webhook
Bug R-2: customId status_page_-1 ตอน first page → parse เป็น NaN
บรรทัด ~325:
let page = 0;
if (customId.startsWith("status_page_")) {
    page = parseInt(customId.split("_")[2]) || 0;
}
if (page < 0) page = userSessions.length - 1;

ปัญหา: parseInt("-1") = -1 → ตก if (page < 0) → page = length - 1 ✅ OK

Bug R-5: cleanupGuild ลบแค่ panelMessages ใน RAM ไม่ลบ PanelStateModel ใน DB
function cleanupGuild(guildId) {
    panelMessages.delete(guildId);
}

→ ตอน guildDelete event → state ค้างใน DB → restorePanels ครั้งต่อไป loop เจอ guild ที่ไม่อยู่แล้ว
