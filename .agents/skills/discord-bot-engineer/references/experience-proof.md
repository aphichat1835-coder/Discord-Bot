# Experience proof

## Contents

- Structural contract
- Behavior proof
- Localization and accessibility
- Visual/live proof
- Anti-generic gate

## Structural contract

Render framework-neutral experience state before transport. Snapshot only representative materially different states/locales and normalize volatile IDs/timestamps—not phase, controls, counters, copy, permission, or errors.

Validate state coverage, surface compatibility, action uniqueness, terminal controls, progress bounds, placeholders, and message limits with bundled tools. Structural snapshots cannot prove Discord rendering, hierarchy, mobile layout, motion, or authorization.

## Behavior proof

Test transitions and response ownership, authorization, stale/forged controls, duplicate/concurrent action, cancellation, partial side effects, publish failure, terminal writer shutdown, restart/persistence, and retry/idempotency.

Use the shared Progress Reporter only for coalescing/rate-bounding presentation. It is not a job store, cancellation primitive, transaction, distributed lock, or retry engine.

## Localization and accessibility

Audit missing/extra keys, empty values, placeholder style/name/type/count, whitespace, newline and Markdown balance. Manually review voice, translation, cultural fit, plural behavior, long names, truncation, and fallback.

Meaning must survive without color/emoji/motion. Provide clear labels, focus order, keyboard access, status announcements on dashboards, sufficient contrast, static equivalents, and reduced-motion behavior. Distinguish disabled from read-only.

## Visual/live proof

Preview loading, empty, denied, partial, success, failure, cancellation, timeout, and long-content states. Test desktop/mobile widths and actual Discord clients when risk justifies it. A generated HTML preview is an approximation, never proof of Discord client rendering.

## Anti-generic gate

Reject unexplained template defaults, identical panels with swapped colors, decorative status loops, fake progress, success that hides partial failure, contextually wrong, mechanically repeated, or placement-inappropriate assistant copy, inaccessible state cues, multiple competing primary actions, fashion-only cards/glow/glass, or motion without a user problem. Judge whether each text element is appropriately brief or detailed for its role—not by one global length preference.

The gate is not “pretty.” It is understandable, truthful, efficient, accessible, operable, coherent with the product, and proven in representative states.
