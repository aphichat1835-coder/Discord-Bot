# Experience Quality Engine

Treat experience as task clarity, information architecture, state truth, interaction cost, accessibility, recovery, perceived performance, brand character, and visual craft.

## Workflow

1. Model the actor, frequency, decisions, risk, environment, and product voice.
2. Audit the current end-to-end flow, navigation, hierarchy, repetition, copy, feedback, error recovery, responsive behavior, and visual consistency.
3. For a substantial redesign, derive two or three materially different directions from product context or supplied references. Explain trade-offs; obtain direction acceptance before large implementation.
4. Design applicable default, loading, processing, empty, success, warning, denial, partial, failure, expired, cancelled, retry, and recovery states.
5. Compile the chosen state model to Discord or dashboard conventions. Progress must derive from real work units.
6. Render and interact with the result. Inspect desktop/narrow or Discord client surfaces, long content/locales, keyboard/focus where applicable, reduced motion, and failure states.
7. Attack generic AI defaults: unjustified purple gradients, glass everywhere, nested rounded cards, copy density that ignores placement, one voice forced onto every command, equal visual weight, vague errors, fake metrics/progress, and decorative motion. A short status and a detailed recovery panel can both be correct.
8. Pass the experience gate only with flow, states, surface/responsive behavior, accessibility, copy, truthful feedback, and visual evidence. Major redesigns also require direction acceptance.

## Discord constraints

Choose plain, ephemeral, embed, Components V2, modal, follow-up, edited progress, thread/DM, or dashboard link based on task—not decoration. Bind private controls to actor/session and disable or expire terminal controls.

Current Discord documentation states interactive `custom_id` values are 1–100 characters, button labels have a platform maximum of 80 characters, Action Rows group up to five buttons or one select, and `IS_COMPONENTS_V2` messages cannot mix traditional content/embeds with component-driven content. Reconfirm version-sensitive details from current official documentation or installed framework types before implementation:

- https://docs.discord.com/developers/components/reference
- https://docs.discord.com/developers/components/overview
- https://docs.discord.com/developers/resources/message

Static anti-pattern matches are prompts for design review, not objective proof that a design is bad.
